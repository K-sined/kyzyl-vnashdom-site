# Сайт «В наш дом» (Кызыл) — стиль и конвенции

Лендинг магазина стройматериалов в Кызыле. Чистый HTML/CSS/JS без сборки —
`index.html`, `styles.css`, `script.js`. Правки вносятся напрямую в эти файлы.

## Публикация

- Репозиторий: https://github.com/K-sined/kyzyl-vnashdom-site (public)
- Живой сайт: https://k-sined.github.io/kyzyl-vnashdom-site/ (GitHub Pages, build type "legacy", ветка `main`, путь `/`)
- После `git push` GitHub Pages пересобирается сам, но не сразу — чтобы не ждать,
  можно принудительно запустить сборку: `gh api -X POST repos/K-sined/kyzyl-vnashdom-site/pages/builds`,
  статус проверять `gh api repos/K-sined/kyzyl-vnashdom-site/pages/builds/latest`.
- `gh` авторизован через `gh auth login --web` (device code flow).

## Цветовая палитра и типографика

Все цвета — CSS-переменные в `:root` (`styles.css`), тёплая гамма в духе логотипа
(красный/жёлтый/коричневый): `--brown-950…500`, `--cream-100/200`, `--terracotta`,
`--orange-500/400`, `--gold-600`, `--red-600`, `--yellow-400`. Новые оттенки — только
через переменные, не хардкодить hex в разных местах.

Шрифты: заголовки — Lexend (700-800), текст — Source Sans 3. Подключены через
Google Fonts `@import` в начале `styles.css`.

## Hero-блок (стартовый экран)

- Слайд-шоу фонов: 5 фото шоурума (`assets/showroom*.jpg`) кроссфейдят друг друга
  через CSS `@keyframes heroSlideFade` (25s цикл, 5 слайдов по 5s, `animation-delay`
  через `nth-child`), плюс лёгкий постоянный zoom всего стека (`heroSlideshowZoom`).
- Текст синхронизирован с фото 1:1: `.hero__slide-content` — CSS grid, все
  `.hero__slide-text` в одной ячейке, та же анимация и те же delay, что у фото.
  У каждого слайда свой оффер (эйбрбоу + заголовок с акцентным словом + подзаголовок),
  привязанный к конкретной изображённой категории товара.
- Кнопки (`.hero__actions`) вне слайд-стека — не мигают, всегда на месте.
- Хедер (`.header`) — `position: fixed`, прозрачный поверх hero (белый текст с
  text-shadow для читаемости на фото), при скролле (`scroll > 40px`, JS в `script.js`)
  получает класс `.header--scrolled` — сплошной кремовый фон, тёмный текст.
- У `.hero` есть постоянный градиент-скрим сверху (`.hero::before`) — специально,
  чтобы меню не сливалось с текстом на вывесках/ценниках на фото. Не убирать при
  правках — раньше без него шапка накладывалась на надписи в кадре и выглядела грязно.
- Текст hero прижат к левому краю **экрана**, а не центрированного `.container`
  (у `.hero__inner` свой `padding-left: max(24px, 6vw)`, без класса `.container`) —
  иначе на широких мониторах текст «зависает» ближе к центру.

## Карточки преимуществ (`.advantage-card`)

- Композиция: фото сверху (`.advantage-card__media`, 190px, cover) → круглый
  значок-бейдж, «нависающий» на фото (`margin-top: -32px`) → заголовок/текст на
  сплошном цветном фоне снизу.
- У каждой карточки свой оттенок через `--card-tint`/`--card-tint-2`
  (`nth-child`), фото плавно уходит в этот цвет через `::after`-градиент —
  фото не должно выглядеть «приклеенным», а перетекать в фон карточки.
- Фото подбираются **индивидуально под смысл** каждого преимущества, а не общие
  видовые снимки магазина — раньше стояли одинаковые «общие» фото шоурума, это
  не считывалось и было заменено на прицельные фото/сгенерированные сцены под
  каждый текст (ассортимент / консультация / цены).
- Hover: зум фото (`::before` с `transform: scale`) + лёгкий поворот бейджа.
- Появление при скролле: `.reveal` + `.advantage-card.reveal` — усиленная версия
  (translateY + scale), значок дополнительно «выскакивает» с поворотом.
- Секция **не наезжает** на hero (важно!): раньше было `margin-top: -90px`,
  из-за чего карточки перекрывали кнопки в hero — убрано, `margin-top: 0`.
  Не возвращать отрицательный overlap без явного запроса.

## Изображения

- Фото-контент — в `assets/`, **всегда JPEG**, не PNG: PNG-скриншоты/фото весят
  2-2.7 МБ каждый, из-за этого на мобильном интернете фон не успевал/не мог
  загрузиться (было на практике — блок с текстом рендерился, а фото нет).
  Через `sips -s format jpeg -s formatOptions ~70` PNG ужимается до 300-450 КБ
  почти без потери качества на глаз — таким должен быть любой новый фото-ассет.
- Логотип — `assets/logo.png` (растровый, с собственным красным фоном-плашкой,
  не прозрачный) — используется как есть на любом фоне (тёмном/светлом).
- Исходники (несжатые PNG «как есть» из генератора/присланные пользователем) —
  папка `Исходники/`, **в git не коммитятся** (см. `.gitignore`: `/Исходники/*.png`,
  кроме `Logo.png`, который уже был закоммичен раньше и остаётся). Если нужно
  что-то перегенерировать/пересжать — брать исходник оттуда, не тянуть заново
  у пользователя.

## Чат-менеджер (чат-виджет)

- Плавающая кнопка в `.quick-contact` (`#aiManagerLauncher`) открывает окно чата
  (`#aiManagerPanel`) — разметка в `index.html`, стили в `ai-manager.css`,
  логика в `ai-manager.js`. Имена id/файлов остались `aiManager*`/`ai-manager.*`
  по историческим причинам, но клиенту персона не раскрывается как ИИ —
  виджет и system-промпт представляют его просто менеджером магазина
  («Менеджер «В наш дом»»); если клиент спрашивает напрямую, бот ли это —
  отвечает честно, не отрицает.
- Бэкенд — Cloudflare Worker в `ai-manager-worker/` (`src/index.js`): держит
  ключ Anthropic и токен Telegram-бота в секретах, отвечает клиенту на вопросы
  о товарах/магазине (system-промпт с ассортиментом и контактами) и через
  tool `submit_lead` отправляет собранные заявки (имя, телефон, суть запроса)
  в Telegram — так же, как квиз выше отправляет лиды в Google Sheets.
- Каталоги по товарным группам: готовые PDF (Двери, Напольные покрытия,
  Плитка, Панели МДФ/ПВХ — см. `Товары/`) лежат на Google Drive (не в
  git-репозитории сайта — весят 5-31 МБ каждый, раздули бы репозиторий и
  zip для reg.ru). Ссылки прописаны в `ai-manager-worker/src/index.js`
  (`CATALOG_LINKS`) — менеджер сам предлагает прислать каталог, но
  вставляет ссылку в ответ только после явного согласия клиента. Для
  групп без готового каталога (Обои, Краска, Клеи/герметики, Гардины)
  ссылок нет — промпт явно запрещает их выдумывать, вместо этого
  предлагается оставить контакты. Фронтенд рендерит URL из ответа как
  кликабельную ссылку (`linkify()` в `ai-manager.js`, HTML экранируется).
- Адрес воркера прописан в `ai-manager.js` (`AI_WORKER_URL`) — при пересоздании
  воркера или смене поддомена `*.workers.dev` обновить эту константу.
- CORS в воркере ограничен списком `ALLOWED_ORIGINS` (GitHub Pages + reg.ru
  домен) — при добавлении нового зеркала сайта добавить туда origin.
- Деплой воркера: `cd ai-manager-worker && npx wrangler deploy` (нужен
  `wrangler login` и секреты через `wrangler secret put`).

## Общие паттерны разметки

- `.reveal` — базовая scroll-in анимация (fade + translateY), навешивается на
  элементы, которые должны появляться при скролле; стагер по элементам грида
  задаётся в `script.js` (`transitionDelay = i * 40ms`) для `.advantages__grid`
  и `.catalog__grid`.
- `.wave-divider` (inline SVG) — волнистая граница между секциями, цвет через
  класс `wave-fill--*`, подбирается под фон следующей секции.
- Карточки каталога (`.catalog-card`) используют похожий приём с фото/градиентом
  в `::before`/`::after`, что и `.advantage-card` — держать эти два паттерна
  визуально согласованными, если один меняется, посмотреть на другой.
